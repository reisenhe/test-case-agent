# Feature Extraction Skill v2

## 何时使用

当用户提供需求文档（Markdown 格式）时，使用此技能提取功能点。

---

## 工作流程

### 1. 规划任务

使用 `write_todos` 规划提取工作：

```
- [ ] 识别主要功能模块
- [ ] 提取每个功能的测试点
- [ ] 识别输入参数和边界条件
- [ ] 分类：正向/边界/异常/性能/安全
- [ ] 分配优先级（P1-P5）
- [ ] 生成测试建议
```

### 2. 分析需求文档

#### 2.1 识别功能模块

将需求文档按功能模块划分：

```
模块1: 用户认证
  - 登录功能
  - 注册功能
  - 密码找回

模块2: 订单管理
  - 创建订单
  - 取消订单
  - 订单查询
```

#### 2.2 识别输入参数（重要！）

对于每个功能点，**必须识别输入参数**：

```
功能点: 用户登录
输入参数:
  - 用户名: 字符串, 3-20字符, 必填
  - 密码: 字符串, 6-20字符, 必填
  - 记住我: 布尔, 可选
```

这些参数信息将用于：
- 边界值测试用例生成
- 输入验证测试用例生成

#### 2.3 识别边界条件

自动识别需要边界测试的场景：

| 参数类型 | 边界场景 |
|---------|---------|
| 字符串长度 | 最小长度、最大长度、空值 |
| 数值范围 | 最小值、最大值、0、负数 |
| 日期时间 | 最早日期、最晚日期、当前时间 |
| 列表选择 | 第一项、最后一项、空选择 |
| 文件上传 | 最小大小、最大大小、不允许的类型 |

### 3. 提取功能点

对于每个功能点，输出以下结构：

```json
{
  "id": "FP-001",
  "name": "功能名称",
  "category": "正向功能",
  "description": "详细描述",
  "preconditions": ["前置条件1"],
  "input_parameters": [
    {
      "name": "参数名",
      "type": "string|number|boolean|date|...",
      "required": true,
      "constraints": "长度3-20字符"
    }
  ],
  "test_suggestions": [
    "验证正确凭据登录成功 (P1, 正向)",
    "验证记住密码功能 (P2, 正向)",
    "验证用户名为空提示 (P3, 逆向)",
    "验证密码错误提示 (P3, 逆向)",
    "验证用户名最大长度限制 (P4, 边界)"
  ],
  "priority": "P1"
}
```

### 4. 质量标准

- **原子性**：每个功能点应是可独立测试的最小单元
- **可验证性**：每个功能点必须有明确的验证方式
- **完整性**：覆盖所有需求描述的功能
- **无冗余**：功能点之间不应有重叠
- **参数完整**：识别所有输入参数及其约束

### 5. 与用户确认

提取完成后，**必须**调用 `confirm_features` 工具触发用户确认。

用户可以：
- **approve**：批准功能点列表
- **edit**：修改后批准
- **reject**：拒绝并要求重新提取

## 分类指南

| 分类 | 说明 | 识别方法 | 预期用例数 |
|------|------|---------|-----------|
| **正向功能** | 正常业务流程 | "可以"、"支持"、"能够"等描述 | 3-5 |
| **边界条件** | 边界值、极限值 | 数值范围、长度限制、时间限制 | 3-4 |
| **异常处理** | 错误输入、异常状态 | "失败"、"错误"、"异常"、"不存在" | 2-3 |
| **性能相关** | 响应时间、并发 | "响应时间"、"性能"、"并发" | 2-3 |
| **安全相关** | 权限、数据安全 | "权限"、"加密"、"认证"、"授权" | 2-3 |

---

## 优先级定义（P1-P5）

| 优先级 | 定义 | 功能点示例 |
|--------|------|-----------|
| **P1** | 核心功能，阻塞发布 | 用户登录、订单创建、支付 |
| **P2** | 重要功能，应该测试 | 记住密码、订单取消、退款 |
| **P3** | 异常处理，必须覆盖 | 错误提示、边界异常、网络超时 |
| **P4** | 边界条件，建议测试 | 长度限制、数值边界 |
| **P5** | 低频场景，可选测试 | 极端边界、罕见组合 |

---

## 测试建议生成规则

### 正向功能测试建议

```
必须包含：
1. P1 核心成功场景
2. P2 次要成功场景或变体

按需包含：
3. P3 输入验证失败
4. P4 边界值验证
```

### 边界条件测试建议

```
必须包含：
1. P4 最小值/下边界
2. P4 最大值/上边界

按需包含：
3. P4 边界外值（min-1, max+1）
4. P3 边界异常处理
```

### 异常处理测试建议

```
必须包含：
1. P3 主要异常场景
2. P3 次要异常场景
```

### 安全相关测试建议

```
必须包含：
1. P1 权限验证成功
2. P3 权限验证失败

按需包含：
3. P3 安全攻击测试（SQL注入、XSS等）
```

## 完整示例

### 输入需求文档

```markdown
# 用户登录模块

## 功能需求

1. 用户可以使用用户名和密码登录系统
2. 用户名长度 3-20 字符，只能包含字母、数字、下划线
3. 密码长度 6-20 字符，必须包含字母和数字
4. 支持"记住密码"功能，下次自动填充凭据
5. 登录失败时显示"用户名或密码错误"提示
6. 连续错误 5 次后锁定账户 30 分钟

## 非功能需求

- 登录响应时间 < 2 秒
- 密码必须加密传输
```

## 重要提示

1. **必须调用 confirm_features 工具**：提取完成后必须调用此工具触发用户确认
2. **不要导出**：导出由系统统一处理，不是你的职责
3. **识别输入参数**：每个功能点都应识别输入参数及其约束
4. **生成测试建议**：测试建议应具体，包含优先级和类型
5. **优先级统一**：使用 P1-P5，不要使用 P0
