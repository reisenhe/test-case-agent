# Test Case Generation Skill v3

## ⚠️ 重要规则

1. **只输出 JSON**：严格按 Schema 输出
2. **不要导出**：导出由系统统一处理
3. **遵守全局约束**：必须遵守"全局测试上下文"中的所有约定
4. **满足覆盖率目标**：确保生成的用例达到覆盖率要求

## 何时使用

当需要为单个功能点生成测试用例时使用。

---

## 第一阶段：场景识别（必须执行）

在生成用例前，**必须先识别测试场景**。不要跳过这一步！

### 1.1 识别输入参数

分析功能点的描述，识别所有输入参数：

```
参数名 | 类型 | 是否必填 | 边界条件
------|------|---------|----------
用户名 | 字符串 | 是 | 长度 3-20 字符
密码 | 字符串 | 是 | 长度 6-20 字符
记住我 | 布尔 | 否 | -
```

### 1.2 识别测试场景

根据参数和业务逻辑，识别以下场景：

| 场景类型 | 识别方法 | 必须覆盖 |
|---------|---------|---------|
| **有效等价类** | 正常业务流程、成功场景 | ✓ |
| **无效等价类** | 输入验证失败、权限不足、资源不存在 | ✓ |
| **边界值** | 每个范围型参数的 min/max/空值 | 如有范围型参数 |
| **特殊场景** | 并发、超时、网络异常 | 根据业务判断 |

### 1.3 场景识别示例

**功能点**：用户登录（正向功能）

**识别的输入参数**：
- 用户名（字符串，3-20字符，必填）
- 密码（字符串，6-20字符，必填）
- 记住我（布尔，可选）

**识别的测试场景**：

| 场景 | 类型 | 说明 |
|-----|------|------|
| 正确凭据登录 | 有效等价类 | 核心成功场景 |
| 记住密码登录 | 有效等价类 | 次要成功场景 |
| 用户名为空 | 无效等价类 | 输入验证 |
| 密码错误 | 无效等价类 | 业务异常 |
| 用户名超长 | 边界值 | 20字符+1 |
| 密码最短 | 边界值 | 6字符 |

## 第二阶段：按场景生成用例

### 2.1 增强的生成规则表

根据功能点分类和场景识别结果，生成用例：

| 功能点分类 | P1 | P2 | P3 | P4 | P5 | 目标数量 |
|-----------|----|----|----|----|----|---------|
| **正向功能** | 1-2 | 1-2 | 0-1 | 0-1 | 0 | **3-5** |
| **边界条件** | 0 | 0 | 0-1 | 2-3 | 0 | **3-4** |
| **异常处理** | 0 | 0 | 2-3 | 0 | 0 | **2-3** |
| **性能相关** | 0 | 0 | 1-2 | 0-1 | 0 | **2-3** |
| **安全相关** | 1 | 0 | 1-2 | 0 | 0 | **2-3** |

### 2.2 详细生成规则

#### 正向功能（目标 3-5 个用例）

```
必须生成：
1. P1 核心正向：主要业务流程成功场景
2. P2 基本正向：次要成功场景或业务变体

按需生成：
3. P2/P3 不同角色/状态：如有多种用户角色
4. P3 输入验证失败：如有输入参数
5. P4 边界值：如有范围型输入参数
```

#### 边界条件（目标 3-4 个用例）

```
必须生成：
1. P4 下边界验证：最小值或空值
2. P4 上边界验证：最大值

按需生成：
3. P4 边界外验证：min-1 或 max+1
4. P3 边界异常：边界外的异常处理
```

#### 异常处理（目标 2-3 个用例）

```
必须生成：
1. P3 主要异常：最常见的错误场景
2. P3 次要异常：其他异常场景

按需生成：
3. P2 异常恢复：异常后的正常流程（如适用）
```

#### 安全相关（目标 2-3 个用例）

```
必须生成：
1. P1 权限验证：正确权限访问成功
2. P3 权限拒绝：无权限访问失败

按需生成：
3. P3 安全攻击：SQL注入/XSS等（如有输入参数）
```

## 第三阶段：用例生成

### 3.1 用例模板

```json
{
  "id": "TC-FP-001-001",
  "feature_point_id": "FP-001",
  "title": "[动词]+[对象]+[预期结果]",
  "purpose": "验证...当...时，应该...",
  "priority": "P1",
  "type": "正向",
  "preconditions": [
    "1. 具体的前置条件",
    "2. 系统状态描述"
  ],
  "steps": [
    {
      "step_no": 1,
      "action": "具体的操作动作",
      "test_data": "具体的测试数据值",
      "expected_result": "可验证的预期结果"
    }
  ],
  "postconditions": ["操作后的系统状态"],
  "tags": ["功能模块", "用例类型"]
}
```

### 3.2 质量规范

| 规范项 | 要求 | 正确示例 | 错误示例 |
|-------|------|---------|---------|
| 标题 | 动词+对象+结果 | 输入正确密码登录成功 | 登录测试 |
| 测试数据 | 具体值 | "testuser123" | "用户名" |
| 预期结果 | 可验证 | 显示"登录成功"提示 | 正常显示 |
| 步骤 | 可执行 | 点击"登录"按钮 | 进行登录操作 |

---

## 覆盖率目标

| 类型 | 目标覆盖率 | 验证方法 |
|------|-----------|---------|
| 有效等价类 | 95% | 每个功能点至少1个正向用例 |
| 无效等价类 | 80% | 每个异常场景有对应用例 |
| 边界值 | 90% | 每个范围型参数有 min/max 测试 |

---

## 优先级定义 (P1-P5)

| 优先级 | 类型 | 目标占比 | 说明 |
|--------|------|----------|------|
| P1 | 核心正向 | ~27% | 核心功能，阻塞发布，必须测试 |
| P2 | 基本正向 | ~20% | 重要功能，应该测试 |
| P3 | 核心异常 | ~33% | 异常处理，必须覆盖 |
| P4 | 边界条件 | ~16% | 边界值测试 |
| P5 | 低频场景 | ~4% | 可选测试，边缘场景 |

## 质量检查清单

生成用例后，**必须自检**以下项目：

- [ ] **场景覆盖**：识别的所有场景都有对应用例
- [ ] **正向功能**：至少有 1 个 P1 用例
- [ ] **边界值**：每个范围型参数有 min/max 测试（P4）
- [ ] **异常处理**：主要异常场景已覆盖（P3）
- [ ] **优先级分布**：P1~27%, P2~20%, P3~33%, P4~16%, P5~4%
- [ ] **测试数据**：使用具体值，不是占位符
- [ ] **预期结果**：可验证，不使用"正常"、"应该"等模糊词
- [ ] **步骤完整**：每个步骤都有 action + test_data + expected_result
